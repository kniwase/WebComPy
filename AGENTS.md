# WebComPy — AI Agent Reference

> **For development workflow** (OpenSpec, PR process, agent delegation): see [CONTRIBUTING.md](CONTRIBUTING.md).
> This file is the technical reference for AI agents working on the codebase.

## Dual-Environment Architecture (CRITICAL)

This framework operates in two distinct runtime contexts:

- **Browser (PyScript/Emscripten)**: Reactive system, component rendering, DOM manipulation, routing
- **Server (Standard Python)**: CLI tools, dev server (Starlette+uvicorn), static site generator

When modifying code, always consider which context the code runs in.
`platform.system() == "Emscripten"` is used to detect the browser environment.
Code in `webcompy/` (core), `webcompy_server/`, `webcompy_cli/`, and `webcompy_testing/` is context-sensitive.

## Project Structure

- `packages/webcompy/` — Core/browser package (`webcompy` import name)
  - `components/` — Component system (base classes, decorators, generators)
  - `elements/` — Virtual DOM / HTML element system
  - `signal/` — Reactive state management (Reactive, Computed, ReactiveList, ReactiveDict)
  - `template/` — HTML template engine (`render_template`, `{{ }}` interpolation, void/boolean attrs, reactive attributes via `Computed`)
  - `router/` — Client-side routing (history/hash modes)
  - `app/` — Core application class (`WebComPyApp`, `AppConfig`, `RenderContext` ABC)
  - `di/` — Dependency injection system (provide/inject, DIScope, InjectKey)
  - `ajax/` — HTTP client (browser fetch)
  - `aio/` — Async utilities (AsyncResult, AsyncWrapper)
  - `ui/` — Theme system, code blocks, UI components
  - `ports/_browser/` — Browser port implementations
  - `ports/` — Port ABCs and DI keys
- `packages/webcompy-server/` — Server-side package (`webcompy_server` import name)
  - `_html.py` — HTML generation
  - `_context.py` — `ServerRenderContext(RenderContext)`
  - `ports/` — Server port implementations (ServerDOMPort, etc.)
- `packages/webcompy-cli/` — CLI tools (`webcompy_cli` import name)
  - Dev server, SSG, project scaffolding, wheel builder, lockfile management
- `packages/webcompy-testing/` — Testing utilities (`webcompy_testing` import name)
  - TestRenderer, fake ports, ASGI test client, scope helpers
- `docs_app/` — Documentation site application
- `docs/` — Generated static site (gitignored, generated by CI)

## Commands Reference

### Build & Run

```bash
uv sync                                    # Install dependencies
uv sync --all-groups                       # Install all deps (incl. matplotlib/numpy)
uv run python -m webcompy start --dev      # Dev server (default port: 8080)
uv run python -m webcompy generate         # Static site generation
uv run python -m webcompy init             # Project scaffolding
uv build                                   # Build package
```

### Lint, Type Check & Test

```bash
uv run ruff check .                        # Lint
uv run ruff format .                       # Format
uv run ruff format --check .               # Format check
uv run pyright                             # Type check
uv run python -m pytest tests/ --tb=short  # Unit tests only (E2E tests live in e2e/, see below)
uv run python -m pytest tests/ --tb=short --cov=webcompy --cov-report=term-missing  # With coverage
scripts/run-e2e-tests.sh                   # All E2E tests (core + docs, prod + static)
scripts/run-e2e-tests.sh <group-name>      # Single E2E group (e.g., components, docs-home)
```

### Inspect CLI

Browser-based inspection for debugging and verification. Requires Playwright.

```bash
uv run python -m webcompy inspect serve --config docs_app.webcompy_config --port 0   # Start server
uv run python -m webcompy inspect stop <port>                                          # Stop server
uv run python -m webcompy inspect screenshot <url> [--full-page] [--selector sel]     # Screenshot
uv run python -m webcompy inspect console <url> [--level error]                        # Console logs
uv run python -m webcompy inspect query <url> "h1" [--property text]                   # DOM query
uv run python -m webcompy inspect click <url> "#btn" [--wait-for .result]               # Click
uv run python -m webcompy inspect navigate <url> "/path" [--wait-for "#page"]           # Navigate
uv run python -m webcompy inspect verify <url> --expect "h1=Title"                      # Assertions
```

## Code Conventions

- Python 3.12+ (aligned with latest PyScript/Pyodide runtime)
- Package management with `uv` — use `uv add <package>` to add dependencies, `uv lock` to update lockfile
- Type annotations throughout (package includes `py.typed` marker and `.pyi` stubs)
- No comments in code unless explicitly requested
- Component classes use decorators: `@component_template`, `@on_before_rendering`
- Reactive state primitives are specified in `openspec/specs/reactive/spec.md` and `openspec/specs/composables/spec.md`. New transfer-capable state SHOULD be created via `use_state` / `use_reactive_list` / `use_reactive_dict` composables inside component setup so the SSR transfer path works.

### Naming Conventions

- Public Python functions and variables use `snake_case`.
- Classes and exceptions use `PascalCase`.
- Module-private names use a leading underscore (`_private_name`).
- Constants use `UPPER_CASE`.
- WebComPy composables follow the `use_verb` / `use_noun` pattern in `snake_case` (e.g., `use_state`, `use_router`, `use_async`, `use_async_result`).
- DOM and browser API wrappers may use `camelCase` **only** when intentionally mirroring a standard web API name (e.g., `setAttribute`, `appendChild`, `addEventListener`). Public APIs that are not direct web-standard wrappers must use `snake_case`.

## App Instance API

- `WebComPyApp` is the central application object:
  - `app.run(selector="#webcompy-app")` — Browser entry point (raises if not in Emscripten)
  - `app.di_scope` — DI scope context manager for server-side rendering
- Server entry points use `create_asgi_app(app, server_config=None)` and `run_server(app=None)` from `webcompy_cli`
- SSG uses `generate_static_site(app=None, generate_config=None)` from `webcompy_cli`
- Configuration: `AppConfig` (base_url, dependencies, assets, app_package)
- `app.__component__` is deprecated — use forwarded properties: `app.routes`, `app.router_mode`, `app.set_path()`, `app.head`, `app.style`, `app.scripts`, `app.set_title()`, etc.
- Per-app state: Each `WebComPyApp` owns its own `ComponentStore` and `_defer_*` rendering state
- DI scope is managed via `app.di_scope` context manager — no global `_root_di_scope`

## Review Knowledge Maintenance

`openspec/specs/` is the single source of truth for requirements and API naming. Universal docs (`AGENTS.md`, `CONTRIBUTING.*`, `.opencode/skills/*/SKILL.md`) SHALL reference specs, not transcribe them. When specs are added, modified, or removed, update:

1. The **File → Spec Mapping** table above
2. The **Framework Invariants** list above and the **Critical Framework Invariants** section in `.opencode/skills/webcompy-review/SKILL.md` (headings + spec references)
3. The **Current Specs List** below
4. Any referencing doc whose spec reference now dangles or whose transcribed content is stale
5. Run `python3 scripts/check-doc-spec-refs.py` and confirm it passes

When a public API is renamed, add the retired name to the blocklist in `scripts/check-doc-spec-refs.py` so docs referencing it fail validation.
