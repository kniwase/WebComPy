# Design: refactor-signal-stream-markdown

## Context

The docs section (`/documents`) renders content pages through two paths: Markdown-backed entries (`source`) load a `.md` resource and render via `docs_page_template` (prose article + TOC aside), while component-backed entries (`component`) render arbitrary Python element trees. Installation and Quickstart use the Markdown path; the signal-stream page still uses a hand-written component tree (`Section`/`InlineCode`/`CodeBlock` inside a `.page-container`), so it lacks prose typography and the TOC aside, and its content can only be edited in Python.

The `docs-site-documents` spec currently pins this state: the signal-stream requirement says the page SHALL remain a Python component ("no Markdown conversion"). That constraint was a migration-scope decision (move the page into the docs section without rewriting it) and is the only thing blocking this conversion.

The page also has a naming split: the manifest label is "Signal Stream" while the rendered H1 is "Signals and Streams".

## Goals / Non-Goals

**Goals:**

- Signal-stream becomes a Markdown-backed page rendered through `docs_page_template`, consistent with Installation/Quickstart (prose typography, TOC aside, scoped style).
- The page name unifies to "Signals and Streams" across manifest label, frontmatter title, H1, sidebar/dropdown/Prev-Next text, and browser title.
- The URL `/documents/signal-stream` and the derived component reference stay unchanged.
- Prose content is preserved verbatim through the format conversion.

**Non-Goals:**

- No manifest schema change (`source`/`component` validation and `page_component_ref` derivation stay as specified).
- No conversion of `DOCS_INDEX` (the index page remains component-backed).
- No rewrite of the prose itself beyond format conversion and the name unification.

## Decisions

### 1. Rewrite the page module in place instead of adding a new one

`page_component_ref` derives `docs_app.pages.document.signal_stream:SignalStreamPage` from the source stem `signal_stream`, which is exactly the existing page module and attribute. Rewriting `pages/document/signal_stream.py` into the async Markdown pattern (mirroring `installation.py`) keeps routing, lazy references, and the manifest derivation untouched. Alternative: a new module plus manifest `component` override — rejected as needless duplication that would also leave a dead module.

### 2. Content conversion mapping

| Component form | Markdown form |
|---|---|
| First `Section` heading "Signals and Streams" | `# Signals and Streams` H1 + intro paragraph |
| Other `Section` headings | `## ` H2 (generates TOC entries) |
| `InlineCode({"text": ...})` | backtick span |
| `CodeBlock({"lang": "python", ...})` | ` ```python ` fenced block |
| `html.STRONG` / `html.EM` | `**...**` / `*...*` |

The four code examples are copied verbatim from the current template. Alternative: keep `CodeBlock` via a custom Markdown directive — rejected; fenced blocks already render through the shared Markdown pipeline with highlighting.

### 3. Unify the name to "Signals and Streams"

Frontmatter `title`, H1, and manifest label all use "Signals and Streams", matching the existing H1 and the title==H1 convention of the other docs pages. The browser title becomes "Signals and Streams - WebComPy Docs" via the frontmatter-driven `set_title`. Alternative: unify to "Signal Stream" — rejected; the plural form is the established document heading and reads naturally as a topic title, while the URL slug `signal-stream` stays as-is.

### 4. Delete the component template

`templates/document/signal_stream.py` has no other consumers and is removed. The shared `Section`/`InlineCode` UI components stay (home and not-found pages still use them).

## Risks / Trade-offs

- [Converted prose drifts from the original wording] → Convert sentence-by-sentence from the existing template; E2E asserts the H1 and layout, and the diff is reviewable against the deleted template.
- [Browser title / label text change breaks assertions elsewhere] → Grep shows exactly five E2E/manifest occurrences of "Signal Stream"; all are updated in this change.
- [TOC heading ids for headings containing colons ("to_signal: one-shot values")] → Heading ids are generated by the shared Markdown parser already used by the other docs pages; TOC anchor E2E coverage on this page verifies the links.
- [Spec drift if merged before `feat-docs-document-pages` (#247)] → This branch is based on that branch's tip; the delta MODIFIES requirements introduced by it, so it must merge after #247.

## Migration Plan

Single branch, no data migration. Rollback = revert the merge commit; the URL never changes, so no redirects are needed.
